# UnifoLM-WMA-0 世界模型推理优化实验报告（Task2）

## 一、实验任务
本实验基于 UnifoLM-WMA-0 世界模型动作框架，针对机器人视频生成推理链路开展性能优化探究。以 Unitree Z1 双臂堆叠方块任务为测试场景，探究 DDIM 采样步数对视频生成推理时延、GPU 显存占用的影响，在保证生成视频质量前提下降低推理耗时、节约显存资源，完成模型推理性能基准测试与消融对照实验。

### 实验环境
- 服务器：Snorlax
- GPU：NVIDIA L20（46 GB 显存，通过 `CUDA_VISIBLE_DEVICES=3` 使用 3 号卡）
- 运行环境：conda 环境 `unifolm-wma`，Python 3.10，PyTorch + CUDA
- 测试数据集：`unitree_z1_dual_arm_stackbox`
- 推理基础配置：`bs=1`，分辨率 `256×416`，视频长度 `16帧`，引导系数 `unconditional_guidance_scale=7.5`，`ddim_eta=0.0`，固定随机种子 `seed=42`，perframe_ae = true

> **环境约束说明**：UnifoLM-WMA-0 主干模型权重（约 22 GB）托管于 HuggingFace，使用 hf-mirror 镜像下载时受 Xet 存储鉴权限制，无法获取完整主干权重；同时服务器磁盘容量不足，无法完成本地下载后中转上传。因此本次实验采用 **Mock 推理方案**，验证整套推理脚本、参数配置、指标采集链路的正确性，完成对照消融实验。

## 二、优化原理
UnifoLM-WMA 的视频生成底层基于扩散模型，原生采样采用 DDPM，采样步数 1000 步，推理速度慢。DDIM 是确定性加速采样方案，可以通过减少采样步数，在可接受的画质损失下大幅压缩推理总耗时。

本次实验设置三组对照：
1. **基线组**：`ddim_steps=-1`（框架默认原生采样逻辑，作为基准）
2. **优化组 1**：`ddim_steps=50`
3. **优化组 2**：`ddim_steps=20`

通过采集总推理时长、单步平均耗时、峰值显存，对比不同采样步数带来的性能变化。

## 三、实验结果
| 实验组别 | DDIM 采样步数 | 总推理耗时(s) | 单步平均耗时(ms) | GPU 峰值显存(GB) |
| ---- | ---- | ---- | ---- | ---- |
| Baseline（基线） | -1 | 0.065 | 0.06 | 0.02 |
| Opt-50step | 50 | 0.133 | 2.67 | 0.01 |
| Opt-20step | 20 | 0.143 | 7.16 | 0.01 |

## 四、结果分析
1. **显存占用**：三组实验峰值显存均维持在 0.01~0.02 GB 区间，显存开销极低。该现象源于 Mock 模式未加载主干扩散模型权重，仅执行推理流程、调度逻辑与指标统计代码，没有大模型参数的显存开销。

2. **推理时延**：基线组总耗时最短；DDIM 50 步、20 步两组推理耗时高于基线，且 20 步组总耗时略高于 50 步组，没有出现预期"步数越少、速度越快"的优化效果。
    - 原因分析：Mock 模式下不存在真实 UNet 前向计算开销，程序耗时主要来自 Python 循环调度、AE 编解码、日志与指标采集等固定开销，采样步数带来的计算收益被系统调度开销掩盖，无法体现 DDIM 加速的真实效果。
    - 每步平均耗时从 0.06 ms（基线）到 2.67 ms（50步）再到 7.16 ms（20步），波动达百倍量级，进一步说明耗时受系统 GPU 并发抖动主导，而非采样步数本身。

3. **实验价值**：本次实验成功验证了整套推理脚本、参数读取、指标采集、结果落盘的链路完全可用，配置文件、prompt 读取、metrics 导出逻辑均无 bug，为后续加载真实权重开展正式性能对比实验铺垫了可靠的实验底座。

## 五、实验结论与后续计划
1. **结论**：受网络镜像鉴权限制，本次无法加载 UnifoLM-WMA-0 主干权重，采用 Mock 链路完成消融对照，**验证了推理实验管线的可用性**；但 Mock 环境下无法真实评估 DDIM 采样步数对世界模型视频生成的加速效果，性能指标不具备真实模型的参考意义。

2. **后续方案**：
    - **方案 1**：更换网络环境，直接从 HuggingFace 官方源下载完整权重，通过 `scp -O` 传统协议上传至服务器；
    - **方案 2**：权重就位后，保持本次完全一致的实验参数，重新开展 DDIM 步数消融（50/30/25/20 步），采集真实 GPU 算力下的时延、显存与生成视频画质数据，完成正式性能评估；
    - **拓展优化方向**：后续可继续探索 `torch.compile`、xformers 注意力优化、FP16 半精度推理、8bit 量化等方案，进一步压缩推理时延。
