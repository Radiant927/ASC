# Task1：HPL/HPCG 基准测试与 CPU-GPU 算力对照实验报告

## 一、实验环境
| 项目 | 配置 |
|------|------|
| 服务器 | Snorlax 集群（内网地址已隐去） |
| CPU | 双路 Intel Xeon Platinum 8352V，共 72 核 |
| 内存 | 503 GB |
| GPU | NVIDIA L20（46 GB 显存） |
| OS | Ubuntu 22.04 (Linux x86_64) |
| 编译器 | GCC 11.x |
| MPI | OpenMPI |
| BLAS | OpenBLAS |

## 二、HPL 基准测试
### 2.1 编译
使用 HPL 2.3 源码，GCC 11.x 编译，MPI 并行，链接 OpenBLAS 数学库，生成 `xhpl` 可执行文件。

### 2.2 运行配置
36 个 MPI 进程，问题规模 N=20000，分块 NB=192，6×6 进程网格；采用 Crout 分解、2ring 广播策略。完整参数见 `HPL.dat`。

### 2.3 实测结果
| 指标 | 数值 |
|------|------|
| 求解规模 N | 20000 |
| 分块 NB | 192 |
| 进程数 | 36（6×6） |
| 运行耗时 | 6.04 s |
| 实测性能 | **883.06 GFLOPS** |
| 残差校验 | PASSED（残差 1.45335402e-03） |

### 2.4 功耗说明
本次实验未接入功率计，也未从机房监控系统采集整机功耗；功耗 < 3 kW 为赛题给定约束条件，实验过程在该功耗上限内开展，无原生实测功耗读数。

### 2.5 原始输出与复跑命令
xhpl 原始输出日志未随报告归档，复跑命令如下（在 HPL 构建目录执行）：

```bash
mpirun -np 36 ./xhpl > hpl_N20000_36p.log
```

## 三、HPCG 基准测试
### 3.1 赛题要求
HPCG 3.0，运行时间不少于 1800 s，且不允许使用 Quick Path 选项。

### 3.2 尝试情况
在服务器上尝试 HPCG 3.0 的编译与运行，未能跑通完整的 30 分钟基准测试。当前环境仅有登录节点可用，缺少可提交长时间 MPI 作业的入口；具体报错日志未归档，后续需在具备作业提交能力的节点上复跑并留存输出。

### 3.3 替代方案
受此环境限制，本次改用**稠密矩阵乘法（GEMM）作为代理算例**，对比 CPU 与 GPU 的浮点算力，间接反映服务器计算能力与访存带宽特性。

## 四、GEMM 代理算例实验
### 4.1 实验设计
- 算例：稠密矩阵乘法 C = A×B，浮点运算量 = 2N³
- CPU：numpy, float64；GPU：PyTorch, float32（含预热，CUDA 同步计时）
- 指标：耗时(s) 与 GFLOPS = 2N³ / 耗时 / 1e9

### 4.2 实验结果
| 设备 | 矩阵规模 | 耗时(s) | GFLOPS |
|------|---------|---------|--------|
| CPU  | 1024×1024 | 0.011 | 198.39 |
| CPU  | 2048×2048 | 0.020 | 863.83 |
| CPU  | 4096×4096 | 0.097 | 1418.70 |
| GPU(L20) | 2048×2048 | 0.002 | 7289.59 |
| GPU(L20) | 4096×4096 | 0.007 | 19151.52 |
| GPU(L20) | 8192×8192 | 0.061 | 17902.23 |

### 4.3 结果分析
1. CPU 算力随矩阵尺寸增大而上升，4096 规模达到 1418.70 GFLOPS，符合 BLAS 库对大矩阵的优化效果。
2. GPU 算力远高于 CPU，4096 规模达到峰值 19151.52 GFLOPS，约为 CPU 的 13.5 倍，体现 GPU 大规模并行计算优势。
3. 矩阵增大至 8192×8192 时，GPU 算力从 19151 略降至 17902 GFLOPS，说明此时性能瓶颈由计算单元转移到显存带宽，符合 GPU 计算-访存 Roofline 模型规律。
4. 综合 HPL 883.06 GFLOPS 与 GEMM 对照，该节点 CPU 侧浮点性能受多核并行与内存带宽制约，GPU 侧具备显著算力优势，适合大规模稠密浮点运算。

## 五、结论
1. HPL 标准跑分在 36 进程下达到 883.06 GFLOPS，残差校验通过，结果有效（GCC + OpenMPI + OpenBLAS）。
2. HPCG 3.0 因缺少长时间 MPI 作业提交入口，未能完成 1800 s 正式跑分；改用 GEMM 代理算例完成算力对照。
3. GEMM 实验表明 NVIDIA L20 GPU 峰值算力约 19 TFLOPS（FP32），约为同期 CPU（1.4 TFLOPS）的 13 倍；大矩阵下出现带宽瓶颈，与理论 Roofline 模型一致。
